# Scoped paid status and redemption extension (local source candidate)

The existing installation-billing v1 canonical frame and domain separation remain unchanged. Four exact operations extend the closed inventory: `session.paid.status`, `session.redeem`, `paid.status`, `redeem`. Their routes are respectively `/v1/installation-billing/sessions/paid-status`, `/v1/installation-billing/sessions/redemption`, `/v1/installation-billing/paid-status`, `/v1/installation-billing/redemption`. These are seller issuer routes; control-plane never proxies the private mux.

Session acquisition uses the existing empty body, five-minute session, five-minute challenge, request scope, clock-skew rules and registered key proof. Paid status body has exactly `attemptId`, `cursor`, `limit` (1–25). Empty attempt selects an exact owner keyset page; cursor is an opaque attempt position, at most128 bytes. Redemption body has exactly `attemptId` and `nonce`; nonce is canonical unpadded base64url of24 bytes, rejecting the all-zero value. The control-plane owns and durably persists the nonce; browser input selects an attempt only. Caller-selected license/customer/purchase is forbidden.

The request binds the existing method, exact route, canonical body digest, seller/test mode, installation, tenant, audience, epoch, request identity and original deadline. Session possession alone is insufficient. An identical business retry keeps the exact intent/body/deadline but obtains a new signed challenge; it never reuses a consumed challenge. No general redemption, issuance-retry, operator or signer operation is exposed.

Response adds only optional `paidStatus` and `activationCode`. Old operations must omit both, including null values; all old vectors remain byte-identical. `paid.status` requires paidStatus only. `redeem` requires one activation_required paidStatus record and an activationCode. The twelve exact record strings cover attempt/plan/version, subscription/payment/issuance/summary states, purchase/license/current-license and Unix-second expiry/grace. Zero means unknown; timestamp maximum253402300799. At most25 unique attempts appear. Status observation is never payment or grant authority. Activation requires exact persisted paid invoice/outbox/current-license proof. Pending, grace, held, revoked, expired, foreign or unknown historical proof cannot redeem.

Activation code is at most8192 bytes; the existing65536-byte envelope limit still applies. Go/TypeScript enforce closed operation-dependent shapes, unknown/duplicate fields, time and body bounds. The public vector's synthetic v1 token tests envelope encoding only; persisted E2E verifies a real Ed25519 grant with the existing offline verifier. Existing grants and activation formats are unchanged.

This is unpublished source integration over published v0.1.118. No compatible new version is assigned, tagged or published. Consumers use an explicitly temporary external workfile for these checks; their release pins/provenance are unchanged. Publication, consumer pin/snapshot regeneration, independent GOWORK=off builds and hosted checks are separate gates. No enrollment/runtime activation follows from this document.
